When working with Wallet APIs, you may encounter various errors. Here are some common errors and how to troubleshoot them.

### Replacement underpriced

```json
{
  "code": -32602,
  "message": "replacement underpriced",
  ...
}
```

<Info>
  Replacement underpriced errors occur when you attempt to send a call from the
  same sender before a pending call has been confirmed onchain. Follow
  [these
  recommendations](https://www.alchemy.com/support/how-to-fix-replacement-underpriced-errors).
</Info>

### Execution reverted

```json
{
  "code": -32521,
  "message": "execution reverted",
  ...
}
```

<Info>
  This error normally happens if the calls you are attempting to make are
  reverting onchain. Double check that you are calling the correct method on
  the correct contract address, you are using the correct chain, and that the
  method arguments are correct and properly ABI-encoded.
</Info>

### ERC20: transfer amount exceeds balance

```json
{
  "code": -32521,
  "message": "ERC20: transfer amount exceeds balance",
  ...
}
```

<Info>
  If [paying for gas with ERC-20
  tokens](https://www.alchemy.com/docs/wallets/transactions/pay-gas-with-any-token),
  ensure the sender has the required balance.
</Info>

### AA23 reverted

```json
{
  "code": -32500,
  "message": "validation reverted: [reason]: AA23 reverted",
  ...
}
```

<Info>
  AA23 errors happen if sender signature validation reverted or ran out of gas
  (OOG). Follow [these
  recommendations](https://www.alchemy.com/support/how-to-resolve-entrypoint-aaxx-errors).
</Info>

### AA25 invalid account nonce

```json
{
  "code": -32500,
  "message": "validation reverted: [reason]: AA25 invalid account nonce",
  ...
}
```

<Info>
  The nonce used is invalid. This usually happens when trying to reuse an old
  nonce. Follow [these
  recommendations](https://www.alchemy.com/support/how-to-resolve-entrypoint-aaxx-errors).
</Info>

### Policy ID(s) not found

```json
{
  "code": -32600,
  "message": "Sponsorship failed: [invalid_argument] Policy ID(s) not found. Please ensure you're sending requests with the API key associated with the policies' app, that the policies are active, and the network is allowed.",
  ...
}
```

<Info>
  Ensure you're sending requests with the API key associated with the
  policy's app, the policy is active, and the network is allowed. See [gas
  sponsorship
  docs](https://www.alchemy.com/docs/wallets/transactions/sponsor-gas) for more
  info.
</Info>

### Invalid account signature

```json
{
  "code": -32507,
  "message": "invalid account signature",
  ...
}
```

<Info>
  The call was rejected because it contains an invalid signature from the
  sender. Be sure that you are correctly signing the signature request(s). Refer
  to the [Wallet API
  quickstart](/docs/wallets/reference/smart-wallet-quickstart#2-sign-the-signature-requests) for
  more info.
</Info>

### Precheck failed: sender balance

```json
{
  "code": -32000,
  "message": "precheck failed: sender balance and deposit together is ____ but must be at least ____ to pay for this operation",
  ...
}
```

<Info>
  The sender's balance is too low to cover gas fees. This normally happens when
  you mistakenly forget to include your Gas Sponsorship Policy ID. See [gas
  sponsorship
  docs](https://www.alchemy.com/docs/wallets/transactions/sponsor-gas) for more
  info.
</Info>

## Rundler precheck errors

The following errors originate from Rundler's precheck validation and surface through Wallet APIs with error code `-32000`. They indicate that a user operation failed validation before being submitted to the mempool.

### maxFeePerGas too low

```json
{
  "code": -32000,
  "message": "precheck failed: maxFeePerGas is {actual} but must be at least {min}",
  ...
}
```

<Info>
  This error occurs when the base fee on the chain fluctuates between the time you prepare a call and the time you send it. To resolve:

  * Re-prepare the call immediately before sending to get up-to-date fee estimates.
  * Minimize any delay between preparing and sending — don't wait around between the two steps.
  * Optionally, use [fee overrides](/docs/wallets/reference/alchemy-sendpreparedcalls#fee-overrides) to set a higher `maxFeePerGas` buffer.
</Info>

### maxPriorityFeePerGas too low

```json
{
  "code": -32000,
  "message": "precheck failed: maxPriorityFeePerGas is {actual} but must be at least {min}",
  ...
}
```

<Info>
  Same cause as `maxFeePerGas too low` — fee market conditions changed between preparation and submission. Re-prepare the call and send promptly, or use fee overrides to add a buffer.
</Info>

### preVerificationGas too low

```json
{
  "code": -32000,
  "message": "precheck failed: preVerificationGas is {actual} but must be at least {min}",
  ...
}
```

<Info>
  The `preVerificationGas` value doesn't cover the intrinsic overhead of the user operation. Re-prepare the call to get an updated gas estimate. This can happen when the operation's calldata size or the chain's L1 fee conditions have changed.
</Info>

### Total gas limit too high

```json
{
  "code": -32000,
  "message": "precheck failed: total gas limit is {actual} but must be at most {max}",
  ...
}
```

<Info>
  The combined gas limits on the user operation exceed the maximum allowed. Reduce the complexity of your calls or split them into multiple operations.
</Info>

### Sender is not a contract and no initCode

```json
{
  "code": -32000,
  "message": "precheck failed: sender {addr} is not a contract and initCode is empty",
  ...
}
```

<Info>
  The sender address has no deployed contract code, and no `initCode` was provided to deploy one. This usually means the smart account hasn't been deployed yet. Ensure you include the correct `initCode` (or `factory`/`factoryData` for EntryPoint v0.7) so the account is created as part of the first user operation.
</Info>

### Existing sender with initCode

```json
{
  "code": -32000,
  "message": "precheck failed: sender {addr} is an existing contract, but initCode is nonempty",
  ...
}
```

<Info>
  The sender account is already deployed, but the user operation still includes `initCode`. Remove the `initCode` (or `factory`/`factoryData`) field — it's only needed for the first operation that deploys the account.
</Info>

### Factory is not a contract

```json
{
  "code": -32000,
  "message": "precheck failed: initCode indicates factory with no code: {addr}",
  ...
}
```

<Info>
  The factory address specified in `initCode` has no deployed code. Verify you're using the correct factory address for the chain you're operating on.
</Info>

### Paymaster deposit too low

```json
{
  "code": -32000,
  "message": "precheck failed: paymaster deposit is {actual} but must be at least {required} to pay for this operation",
  ...
}
```

<Info>
  The paymaster doesn't have enough deposited in the EntryPoint to cover this operation's gas costs. If you're using a [gas sponsorship policy](/docs/wallets/transactions/sponsor-gas), ensure the policy is funded. If you're using a custom paymaster, top up its EntryPoint deposit.
</Info>

### Paymaster is not a contract

```json
{
  "code": -32000,
  "message": "precheck failed: paymasterAndData indicates paymaster with no code: {addr}",
  ...
}
```

<Info>
  The paymaster address has no deployed code on this chain. Double check the paymaster address and that you're on the correct network.
</Info>

### callGasLimit too low

```json
{
  "code": -32000,
  "message": "precheck failed: callGasLimit is {actual} but must be at least {min}",
  ...
}
```

<Info>
  The `callGasLimit` is below the required minimum. Re-prepare the call to get an accurate gas estimate, or use gas overrides to increase the limit.
</Info>

### verificationGasLimit too high

```json
{
  "code": -32000,
  "message": "precheck failed: verificationGasLimit is {actual} but must be at most {max}",
  ...
}
```

<Info>
  The `verificationGasLimit` exceeds the maximum allowed. This can happen if gas estimation returned an unusually high value. Re-prepare the call or reduce overrides if you've set them manually.
</Info>

### EIP-7702 errors

```json
{
  "code": -32000,
  "message": "precheck failed: EIP-7702 ...",
  ...
}
```

<Info>
  EIP-7702 precheck errors can occur for several reasons:

  * **Not supported / disabled** — EIP-7702 is not available on this EntryPoint or has been disabled on this chain.
  * **Chain ID mismatch** — The authorization's `chainId` doesn't match the target chain. Ensure you're signing for the correct network.
  * **Invalid signature** — The EIP-7702 authorization signature is malformed or was signed by the wrong key.
  * **Sender/authority mismatch** — The recovered signer from the authorization doesn't match the expected sender.
  * **Nonce mismatch** — The authorization nonce doesn't match the expected value on-chain.
  * **Invalid factory** — The factory specified in the EIP-7702 authorization is not valid.
  * **Too many pending transactions** — The authorization sender already has a pending transaction. Wait for it to confirm before sending another.
</Info>
