We're part of [GitHub's secret scanning partner program](https://docs.github.com/en/code-security/secret-scanning/secret-scanning-partnership-program/secret-scanning-partner-program). If an Alchemy key or access token is pushed to a public GitHub repository, GitHub finds it and tells us within minutes.

When that happens:

1. GitHub detects the key in a public repository, gist or issue, and sends it to us.
2. We check the key is real and active.
3. We revoke it, so it can't be used to spend your compute units.
4. We email your team's admins with where it was found and how to replace it.

Your apps keep working with any key that wasn't leaked. Create a new key in the dashboard, update your app, and remove the old key from your repository and its history.

<Tip>
Keep keys out of code. Load them from environment variables or a secrets manager, and add files like `.env` to `.gitignore`.
</Tip>

See [Rotate an Access Token](/docs/how-to-rotate-api-keys) for how to replace a key without downtime, and [IP Allowlisting](/docs/how-to-add-allowlists-to-your-apps-for-enhanced-security) to make a leaked key unusable outside your servers.
