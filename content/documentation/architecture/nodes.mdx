Nodes run the chain: they follow new blocks, execute transactions and keep state. The [engine](/docs/documentation/architecture/engine/routing) sends each request to a node that's healthy and caught up, and takes a node out of rotation when it lags or fails.

## Clients

We run more than one client for a network wherever more than one exists. If a client has a bug, traffic moves to the others, so your app keeps working.

On Ethereum, each node pairs an execution client, which runs transactions and keeps state, with a consensus client, which agrees on which blocks are final. Rollups pair an execution client with a rollup node that follows Ethereum.

## Keeping clients up to date

We track client releases and hard forks long before they activate. See [Node Upgrades](/docs/documentation/ecosystem/node-upgrades), the Release Calendar and the Release Feed.
