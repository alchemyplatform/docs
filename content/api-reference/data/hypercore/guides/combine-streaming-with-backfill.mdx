# Combine streaming with backfill

Streams replay only recent blocks. If a fill stream returns a `gap`, or a client was offline longer than the replay window, the missing range has to come from another source.

1. Record every `gap` range (`fromBlock` to `toBlock`, inclusive) and any outage longer than the replay window.
2. Continue processing live data; don't block on the backfill.
3. Fill the missing range from a historical source, deduplicating on `tid` plus user.

<Callout intent="info">
  HyperCore REST and historical data aren't part of the current beta. To recover a wallet's fills for a missed range, use Hyperliquid's `userFillsByTime` info request, and keep outages short so replay covers them.
</Callout>

Book streams don't need backfill: resubscribe and the snapshot gives you current state.
