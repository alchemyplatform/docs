## Supported networks

A check means the endpoint is supported. A dash means not yet supported or unconfirmed. Coverage can also vary by token.

The **Market and wallet endpoints** column covers token market data (single and batch), token metadata, token OHLCV, token trades, pools for a token, pools (single and batch), pool OHLCV, pool trades, trending pools, search, wallet trades, and wallet PnL.

## Read amounts, timestamps, and identifiers

USD values, token amounts, and percentages are decimal strings; `null` means unknown. Use decimal arithmetic for calculations and convert to JavaScript numbers only when needed for display. Response rows carry an Alchemy `network` slug. Response timestamps, including OHLCV timestamps, use ISO 8601 UTC. Request time parameters also accept Unix seconds.

Token and pool addresses have no network prefixes. DEX details use `dex: { id, name }`. Token `topPools` contains only `{ network, poolAddress }` references. Pool responses have `baseToken` and a primary `quoteToken`; multi-token pools also have `quoteTokens` containing all quote tokens. `feePercent` is available on single and batch pool endpoints.

A trade `id` is unique per swap and has the format `{network}:{txHash}:{logIndex}`. Use it to distinguish multiple trades in one transaction. A trade describes its incoming and outgoing tokens with `tokenIn` and `tokenOut`; `isAnomalous` can help filter unusual activity.

## Chart OHLCV

Pool OHLCV prices the pool’s base token in USD. Token OHLCV describes the selected token. Rows are objects sorted in ascending timestamp order. Empty intervals are omitted; preserve chart gaps instead of filling them with zero prices.

Use `interval` with `1s`, `15s`, `30s`, `1m`, `5m`, `15m`, `1h`, `4h`, `12h`, or `1d`. `to` requests entries before a time, and `limit` accepts up to 1000 entries. Holder-history requests use `days=7`, `days=30`, or `days=max`.

## Continue through pages

Omit `pageKey` on the first request. Pass it back unchanged with the same filters. Stop when the response contains `pageKey: null`. Treat a missing key or a repeated key as an error. A key used with different filters returns `INVALID_ARGUMENT`.

| Endpoint | Pagination |
| --- | --- |
| Token, pool, and wallet trades | `pageSize` defaults to 100; maximum 300. |
| New pools, trending pools, pools for a token, screener | Fixed pages of up to 20; no `pageSize`. |
| Top holders | No `pageKey`. `limit` maximum 50, or 40 on Solana. |
| Holder history, OHLCV, top traders | No `pageKey`. |
| Wallet PnL | Pagination applies to token rows; `pageSize` defaults to 25, maximum 100. |
| Search | Use the returned `pageKey`; no `pageSize`. |
| Batch token market data and pools | Up to 30 items per request; no `pageKey`. |

## Request trade ranges

For token, pool, and wallet trades, provide `from` and `to` together or omit both. The maximum window is exactly 30 days. A longer window, or only one boundary, returns `INVALID_ARGUMENT`. Keep the same boundaries while paging.

## Interpret wallet PnL

Wallet PnL is lifetime only, with `methodology: "average_cost"`. It returns realized and unrealized totals, `byNetwork` totals, and token rows with buy/sell counts, amounts, USD totals, and average prices.

`networks` is required. Use only EVM networks, or `solana-mainnet` alone; mixing them returns `INVALID_ARGUMENT`. `sortBy` accepts `realizedPnlUsd`, `unrealizedPnlUsd`, `boughtUsd`, or `soldUsd`.

## Handle errors and retries

Application errors use `{ "error": { "code": "<CODE>", "message": "<text>" } }`.

| HTTP status | Code | Action |
| --- | --- | --- |
| 400 | `INVALID_ARGUMENT` | Correct the request parameters. |
| 400 | `UNSUPPORTED_NETWORK` | Choose a network supported by the endpoint. |
| 404 | `NOT_FOUND` | Check the address or resource; trader data may be unavailable for the token. |
| 429 | `RATE_LIMITED` | Honor `Retry-After` before retrying. |
| 503 | `UPSTREAM_UNAVAILABLE` | Retry with bounded exponential backoff. |

Empty collections return `200` with an empty list; a missing single resource returns `404`. Honor `Retry-After` as seconds or an HTTP date. Surface exhausted retries and other errors. The [quickstart](/docs/data/trading-api/quickstart) includes retry handling.
