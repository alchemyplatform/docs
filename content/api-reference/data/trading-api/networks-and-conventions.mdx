## Read amounts and timestamps

USD values and token amounts are decimal strings so you can preserve precision. Use decimal arithmetic for calculations; converting these strings to JavaScript numbers can lose precision. `null` means unknown, not zero. Every row carries its Alchemy `network` slug. Other timestamps use ISO 8601 UTC; candle `timestamp` values use Unix seconds UTC.

## Choose token or pool scope

Pool operations describe one pool. Token operations describe the selected token: candles are built from the token’s pool activity. Premium can aggregate across pools. The aggregation request control remains pending. Pool candle price orientation must be checked before comparing it with a token chart. Empty candle intervals are omitted by default; preserve those gaps instead of treating them as zero-volume candles or interpolating prices.

New pool operations return recently created pools. Range requests are limited; split a longer analysis into smaller requests. Time-range boundary inclusion is pending, so account for duplicates when combining adjacent requests.

## Continue through pages

Omit `pageKey` on your first request. Copy each returned opaque key unchanged into the next request, keeping your filters fixed. Stop only when `pageKey` is `null`. Treat a missing key or a repeated key as an error. The proposed `pageSize` default is 25 and maximum is 100. Pagination applies only where an operation exposes it.

## Interpret wallet PnL

General uses average cost for lifetime realized and unrealized PnL, broken down by network and token. Premium reports realized PnL for `1d`, `7d`, `30d` (the default), or `all`. Its history uses hourly buckets for `1d` and `7d`, and daily buckets for `30d` and `all`. Its summary includes trade count, wins, losses, and win rate. The methods and measurement periods differ, so the General and Premium PnL numbers are not comparable.

## Handle errors and retries

Errors use `{ "error": { "message": "..." } }`. Correct a `400` request before retrying and check your API key for `401`. Retry `429` and `503` with bounded exponential backoff. When `Retry-After` is present, wait at least its duration, interpreting either seconds or an HTTP date. Surface other errors and exhausted retries. The [quickstart](/docs/data/trading-api/quickstart) includes TypeScript retry handling.
