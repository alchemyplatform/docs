# Errors and limits

## Error messages

Errors arrive in one of two shapes:

**Subscription error**: the request was understood and rejected. It carries the `subscriptionId` you sent.

```json
{"channel":"subscriptionResponse","subscriptionId":"l2_01","error":{"code":"invalid_params","message":"nLevels must be one of 1, 10, 20, 50; got 7"}}
```

**Connection-level error**: no `subscriptionId`. Sent when a request can't be parsed or attributed to a subscription.

```json
{"channel":"error","error":{"code":"invalid_params","message":"missing field `subscriptionId`"}}
```

Handle both shapes. Some validation errors currently arrive as connection-level errors even when your request included a `subscriptionId`; if you send several subscriptions at once, check which ones were acknowledged.

Branch on `error.code`. Message text is for humans and may change.

## Error codes

| Code | Meaning | What to do |
| --- | --- | --- |
| `invalid_params` | The request is malformed or a parameter is out of range. | Fix the request. The message describes the problem. |
| `already_exists` | The `subscriptionId` is already in use on this connection. | Use a different ID or unsubscribe first. |
| `limit_reached` | A usage limit was hit, such as too many subscriptions on the connection or a duplicate unfiltered subscription. | See [limits](#limits). |
| `book_reset` | A book was re-seeded internally. The subscription stays open and the next message is a snapshot. | Drop local state for that subscription and rebuild from the snapshot. |
| `fills_not_ready`, `book_not_ready` | Temporary internal unavailability. | Retry the subscription after a short delay. |

New codes may be added. Treat unknown codes as errors for the affected subscription.

## Limits

Limits protect shared infrastructure and may change during early access. When you hit one, you receive a `limit_reached` error; existing subscriptions keep working.

* **Subscriptions per connection**: up to 200. Open more connections if you need more.
* **Connections**: up to 1,000 concurrent connections. Contact [abdul.manan@alchemy.com](mailto:abdul.manan@alchemy.com) if you need more.
* **Addresses per subscription**: `users` and `builders` filters accept a bounded list of addresses. Split larger sets across subscriptions.

### Unfiltered subscriptions

Omitting `coins` subscribes to every market. Each connection allows one unfiltered subscription per stream type, and the number of unfiltered streams per team is limited. Unfiltered book streams carry a lot of data:

| Stream (all markets) | Approximate volume |
| --- | --- |
| `l2Book` | ~3 MB/s |
| `l4BookUpdates` | ~1.5–2 MB/s, plus a large initial snapshot |
| `l2BookDiff` | ~0.4 MB/s |
| `bbo`, `allFills` | ~0.1 MB/s |

Volumes vary with market activity. Usage is metered by data delivered, so filter by `coins` where you can. For a live book, `l2BookDiff` carries the same information as `l2Book` at a fraction of the volume.

## Input rules

* Coin names are case-sensitive and must match Hyperliquid's names exactly. An unknown coin is accepted and returns empty data until that market exists, so check spelling. See [markets and coin names](/docs/data/hypercore/concepts/markets-assets-and-dexes).
* Addresses are case-insensitive and are returned lowercase.
* `subscriptionId` can be up to 128 characters.
