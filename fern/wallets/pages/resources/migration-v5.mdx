`@account-kit/wallet-client` is now `@alchemy/wallet-apis`. This guide covers what changed and how to migrate.

## Installation

```bash
npm install @alchemy/wallet-apis@0.0.0-alpha.19 viem
```

Replaces `@account-kit/wallet-client`, `@account-kit/infra`, and `@aa-sdk/core`.

## Import changes

| Before | After |
|---|---|
| `import { createSmartWalletClient } from "@account-kit/wallet-client"` | `import { createSmartWalletClient } from "@alchemy/wallet-apis"` |
| `import { alchemy, sepolia } from "@account-kit/infra"` | `import { alchemyWalletTransport } from "@alchemy/wallet-apis"` + `import { sepolia } from "viem/chains"` |
| `import { LocalAccountSigner } from "@aa-sdk/core"` | `import { privateKeyToAccount } from "viem/accounts"` |
| `import { WalletClientSigner } from "@aa-sdk/core"` | *(remove — pass `WalletClient` directly as signer)* |
| `import { type SmartWalletClientParams } from "@account-kit/wallet-client"` | `import { type CreateSmartWalletClientParams } from "@alchemy/wallet-apis"` |

All chains now come from `viem/chains`, all signers use viem-native types (`LocalAccount` or `WalletClient`).

## EIP-7702 by default

The biggest change: the client defaults to EIP-7702. No more `requestAccount()` → create client → `sendCalls({ from })` dance.

**Before:**

```ts
const clientWithoutAccount = createSmartWalletClient({
  transport: alchemy({ apiKey }),
  chain: sepolia,
  signer,
});

const account = await clientWithoutAccount.requestAccount();

const client = createSmartWalletClient({
  transport: alchemy({ apiKey }),
  chain: sepolia,
  signer,
  account: account.address,
});

await client.sendCalls({
  from: account.address,
  calls: [{ to: "0x...", value: "0x0" }],
});
```

**After:**

```ts
const client = createSmartWalletClient({
  transport: alchemyWalletTransport({ apiKey }),
  chain: sepolia,
  signer: privateKeyToAccount(PRIVATE_KEY),
});

await client.sendCalls({
  calls: [{ to: "0x...", value: BigInt(0) }],
});
```

* No `requestAccount()` needed — call `sendCalls` / `prepareCalls` directly
* No `from` or `account` params needed — defaults to signer address
* No `eip7702Auth: true` capability — 7702 is the default
* `requestAccount()` is still available for [non-7702 smart contract accounts](/wallets/transactions/using-eip-7702#how-to-use-non-7702-mode)

<Note>
  Values are now bigints instead of hex strings (`BigInt(0)` instead of `"0x00"`). You can also use the `0n` literal syntax if your TypeScript config targets ES2020 or later.
</Note>

## Paymaster configuration

`paymasterService` → `paymaster`, `policyId` (top-level) → `paymaster: { policyId }`:

```ts
const client = createSmartWalletClient({
  // ...
  paymaster: { policyId: "your-policy-id" },
});
```

Can also be passed per-call via `capabilities.paymaster`. Supports both `policyId` and `policyIds`.

## Third-party signers

The `WalletClientSigner` wrapper is removed. Pass a viem `WalletClient` directly:

```ts
// Before
const signer = new WalletClientSigner(walletClient, "my-wallet");

// After — just pass walletClient directly
const client = createSmartWalletClient({
  signer: walletClient, // WalletClient with a mounted account
  transport: alchemyWalletTransport({ apiKey }),
  chain: baseSepolia,
});
```

## Full cheat sheet

| Before (v4) | After (v5) |
|---|---|
| `npm install @account-kit/wallet-client @account-kit/infra @aa-sdk/core` | `npm install @alchemy/wallet-apis@0.0.0-alpha.19 viem` |
| `import { createSmartWalletClient } from "@account-kit/wallet-client"` | `import { createSmartWalletClient } from "@alchemy/wallet-apis"` |
| `import { signPreparedCalls } from "@account-kit/wallet-client"` | `import { signPreparedCalls } from "@alchemy/wallet-apis"` |
| `import { swapActions } from "@account-kit/wallet-client/experimental"` | `import { swapActions } from "@alchemy/wallet-apis/experimental"` |
| `alchemy({ apiKey })` | `alchemyWalletTransport({ apiKey })` |
| `LocalAccountSigner.privateKeyToAccountSigner(key)` | `privateKeyToAccount(key)` |
| `new WalletClientSigner(walletClient, "name")` | *(just use `walletClient` directly)* |
| `policyId: "..."` (top-level) | `paymaster: { policyId: "..." }` |
| `paymasterService: { policyId: "..." }` | `paymaster: { policyId: "..." }` |
| `eip7702Auth: true` | *(remove — 7702 is default)* |
| `from: signerAddress` / `from: account.address` | *(remove — defaults to signer address)* |
| `account: signerAddress` (on signing actions) | *(remove — defaults to client account)* |
| `value: "0x0"` / `value: "0x00"` | `value: BigInt(0)` (or `0n`) |
| `await signer.getAddress()` | `signer.address` |

Core method names (`sendCalls`, `prepareCalls`, `signPreparedCalls`, `sendPreparedCalls`, `signMessage`, `signTypedData`, etc.) and all SDK flows are unchanged. JSON-RPC / curl usage is also unchanged.
